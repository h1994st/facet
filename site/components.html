Code block options

Line numbers, wrapping, a title and a terminal frame are CSS only, switched on by attributes. data-f-code-ln, data-f-code-wrap and data-f-code-frame take "true" or "false": on a container (main or article) they set the page's default, and on the block (pre or code) they set that block alone, which wins over the container either way. The article below numbers its code by default, and the third block opts out with data-f-code-ln="false".

Numbered (Giallo's .giallo-l markup); the long line scrolls: 

fn main() {
    let dot = RedDot::new("living-room");

    tracker.follow(dot, Speed::Pounce).expect("the red dot always escapes under the sofa, behind the bookshelf and out past the sunbeam, but the chase is the whole point");
}

Numbered and wrapped (Shiki's .line markup): a wrapped line hangs past its number, the empty line stays, and the first line keeps clear of the Copy button. 

fn main() {
    let dot = RedDot::new("living-room");

    tracker.follow(dot, Speed::Pounce).expect("the red dot always escapes under the sofa, behind the bookshelf and out past the sunbeam, but the chase is the whole point");
}

Opting out of the page's line numbers:

duna feed --bowl kitchen
duna nap --spot sunbeam

A title with no frame: the file name sits in a quiet strip above the code, with the Copy button. 

pub struct RedDot {
    room: String,
}

A terminal frame with a title, around a dark code theme (dark in a light page too): 

$ curl https://example.com/hairball
200 OK  red dot found in the living room, under the sofa, next to the second-best sunbeam

$ duna pounce
  • The title is the pre's data-f-code-title, or data-name (Zola writes ```rust,name=src/main.rs as data-name on code; set data_attr_position = "both" under [markdown.highlighting] to put it on pre too). A long title ends in an ellipsis on one line.
  • On a block, the short names data-ln, data-wrap and data-frame work too: Zola writes a fence's ln=, wrap= and frame= as those, so ```txt,wrap=false keeps one table-like output scrolling sideways.
  • The title is a pseudo-element, which screen readers may not announce. When the name matters, give the pre an aria-label, or wrap the block in a figure with a figcaption.
  • Numbers and wrapping need one element per line as a direct child of code: .giallo-l (Zola 0.23), .line (Shiki, Astro) or [data-line] (rehype-pretty-code). Blocks with the highlighter's own numbers (.giallo-ln from Zola's linenos, or data-line-numbers) are not numbered twice; .giallo-ln takes the same column.
  • Edge cases: a pre > code with no line elements wraps but cannot be numbered. A title or frame needs pre > code; long lines scroll inside code, under a bar that stays put. The number column is 3 characters wide; past 999 lines, widen it with --f-code-ln-width.

Variants

One segmented control switches between versions of the same content, such as two looks of the same screenshots. Radios are the recommended markup: they switch with CSS alone, no JavaScript needed, and arrow keys move between the options. When variants.js loads it takes over and matches by value instead of position. The older button form still works, but only switches with JavaScript.

  • Board
  • Another board

Edge cases:

  • The control's parent is its scope: the control switches every data-f-variant="group:value" inside it. The value is split off at the last colon, so group a and group a:b are distinct.
  • Without JavaScript the match is by position: the nth radio shows the nth variant among its siblings, so each set of alternatives (a gallery item's images, say) shares one parent and follows the radios' order. CSS covers up to six options. With JavaScript the values decide.
  • Without JavaScript, give each radio control its own parent; sibling and nested groups stay independent. A parent with two controls shows every variant until the script runs, which then tells the groups apart by value.
  • A radio's name must be unique in the page (or form), or two controls become one radio group. Each radio sits directly in its label, and each label directly in the control.
  • Radio-form variants carry no hidden; CSS hides them. That rule is layered, so unlayered site CSS that sets display on a variant element (such as img { display: block }) shows it again; add :not([data-f-variant]) to such rules.
  • Browsers without @scope (Firefox before 146, Safari before 17.4) show every variant without JavaScript; with it, switching works as usual.
  • Button form: the control and the non-default variants ship hidden, so without JavaScript the first variant shows and there are no dead buttons. In both forms, a variant whose value has no option stays hidden, a control with no options is skipped, and variants added after init are not picked up (call init again).
Markup 
<!-- Radios (recommended): switch with or without JavaScript -->
<div>
  <div class="f-segmented" role="radiogroup" aria-label="Look" data-f-variants="look">
    <label><input type="radio" name="board-look" value="modern" checked />Modern</label>
    <label><input type="radio" name="board-look" value="classic" />Classic</label>
  </div>
  <ul class="f-gallery">
    <li>
      <img data-f-variant="look:modern" src="modern.jpg" alt="…" />
      <img data-f-variant="look:classic" src="classic.jpg" alt="…" />
      <span class="f-gallery__label">Board</span>
    </li>
  </ul>
</div>

<!-- Buttons: switch only with JavaScript -->
<div>
  <div class="f-segmented" role="group" aria-label="Look" data-f-variants="look" hidden>
    <button type="button" data-variant="modern" aria-pressed="true">Modern</button>
    <button type="button" data-variant="classic" aria-pressed="false">Classic</button>
  </div>
  <img data-f-variant="look:modern" src="modern.jpg" alt="…" />
  <img data-f-variant="look:classic" hidden src="classic.jpg" alt="…" />
